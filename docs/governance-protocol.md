# AxioWeave 治理协议与节点互操作设计 v0.5

日期：2026-11-04。状态：主产品设计草案；已提供模拟表决前快照的离线检查，其余运行协议未实现，不是已发布标准。产品范围见 [README](../README.md)，实施顺序见 [开发方案](development-plan.md)，详细契约见 [决策内核](architecture/decision-kernel.md)，事实依据见 [机制调研](research/governance-evidence-2026-11-04.md)。

最近两轮的服务端契约和验收要求见 [Batch 1 RC 候选](architecture/batch1-rc1-spec.md)。规范冻结、实现符合与真实试点授权是三个独立结论；本次文档合并不宣告其中任一关口达成。

本轮 [对象、动作与依赖增量](architecture/ontology-actions.md) 借鉴产品工程机制，保留多方主张、定性证词、案件隔离及人工授权。动作注册表、血缘标签、模板安装或软件升级都不能自行产生制度权力。

## 1. 核心对象与权力来源

| 概念 | 定义 | 必须区分的边界 |
| --- | --- | --- |
| 共同体 Community | 依一定成员、授权及规则形成的协作组织 | 可以是社区或跨组织联盟，不要求拥有领土或国家地位。 |
| 节点 Node | 由明确运营者负责的 AxioWeave 部署及记录来源 | 技术节点不等于一个国家；一个节点可以承载多个相互隔离的共同体。 |
| 宪章 Charter | 某共同体认可的参与、决定、权限、申诉和修订规则 | 其适用性须说明，不自动覆盖外部法律或其他共同体。 |
| 案件 Case | 有明确问题、参与边界、程序、方案和结果的议题或争议 | 公共讨论、内部决策和争议处理可复用记录结构，程序不同。 |
| 授权 Authority | 可核验的主体、事项、对象或地域、金额及时间范围 | 成员身份、专家资格和管理员角色均不自动产生裁决权。 |
| 决定 Decision | 依某一程序形成的建议、决议或经授权裁定 | 记录结果类型与约束力，不把所有结果叫作“仲裁裁决”。 |
| 承诺 Commitment | 主体对明确条件、资源、期限和责任作出的承诺 | 承诺内容可记录，是否有约束力和是否可执行分别验证。 |
| 互认 Recognition | 接收方对来源节点的某类记录作出的有限接受 | 可按事项、签发者、版本、时间限定；不自动传递。 |

**核心不变式**：改变参与资格、程序状态、资源配置或权利义务的决定与动作，必须绑定版本确定、可解析的授权、证据、范围和救济四元组；生效或执行时重新核验权限与状态。缺失、过期、撤销或存在阻断性争议时不得获得相应效力，拒绝、暂停和恢复同样受约束。该机制用于约束、发现和追责越权，不保证彻底消除风险。

`Draft / Submitted / Effective` 区分材料接收和获得效力。材料不完整的举报、异议或证据仍可按受理程序提交；强类型不成为禁止发声的门槛。法条/协议哈希不是授权充分证明，需核对主体、权能、授权链、范围及状态。具体字段与分层检查见 [决策内核 1.1](architecture/decision-kernel.md#11-batch-1-核心不变式与效力边界)。

## 2. 首版共同体宪章

首版采用固定结构与人工审查支持一种基线程序，不开发任意规则脚本或通用宪法语言。每个案件绑定宪章和程序版本，至少包含：

- 议题范围、发起和反对程序、受影响者识别及外部参与渠道。
- 成员核验、表决资格、代表授权、回避及参与支持。
- 可协商目标与不可交由本次程序交易的约束；约束来源与异议途径。
- 协商、表决和伦理审议的权限划分；法定人数、平票及无法达成一致的处理。
- 结果的咨询或授权性质、执行责任、外部许可和未完成条件。
- 申诉、暂停、独立复核、规则修改、生效时间及退出后的责任处理。
- 数据控制者、公开范围、保存期限、导出与删除程序。

三院制、分层抽签、液态委托可以成为后续模板。受影响度首先用于发现遗漏、安排参与支持和说明风险分布；自动赋予投票权重不是基线功能。权重变更须由明确程序决定，并允许质疑其证据与适用性。

程序权限使用类型化门控：参与程序、证据方法、底线适用、特定同意、授权范围分别审查，不相加成统一权重。门控记录依据、主体、范围、有效期和 `pass / fail / unknown / not_applicable`；必需检查仅凭有效的 `pass` 放行。首版表决前固定参与、底线适用和开轮授权三项；执行权限另查。参与审计披露抽样覆盖、回应和实际参与、支持措施及局限，响应率不单独证明代表性，也不设全产品通用的 60% 门槛。

未知母体和分母显式留空；明确拒绝、未回应、未触达和退出分别记录。补救期限限制等待并要求升级，不允许自动豁免必要同意、适用底线或有效授权。仅预先明确允许的程序性缺口，才可经有权审查披露后继续。紧急协议不能作为通用放行开关。

## 3. 四类程序共用记录，分别授权

| 程序 | 输入与人类角色 | 输出 | 首版支持 |
| --- | --- | --- | --- |
| 协商 Deliberation | 当事人观点、证据、候选方案，主持人与参与者 | 共同点、分歧、条件方案及无协议记录 | 完整流程。 |
| 民主决策 Decision | 冻结的资格、规则、方案，由成员或获授权代表参与 | 建议或内部决议，附计票与理由 | 一人一票基线；后续 QV 仅影子轮次起步。 |
| 伦理审议 Ethical review | 明确争点、相关原则、利益冲突、证据质疑，由回避后的审议组评议 | 有理由的建议、少数意见、转介或暂不判断 | 支持咨询意见，不自动生成人体或生态许可。 |
| 授权仲裁 Arbitration | 已核验的争议范围、仲裁或其他适用授权、审理程序及复核安排 | 具有明确约束范围的裁定及救济路径 | 先模拟；真实约束性仲裁另经专业审查与阶段放行。 |

伦理审议可以提出建议，但不因“伦理”标签而取得普遍约束力。AI 不能担任有最终裁决权的主体。未达成协议、部分协议、暂缓和转交外部机构均是有效结果。

AI 使用限定案件/用途/工具的服务委托，仅提出草稿；调用者拥有受托权不意味着 AI 获得该权。原始材料无法结构化时仍可提交证词与异议，不能因未映射为本体字段而失去程序入口。不同案件的个人资料默认不关联成行为预测或信用档案。

## 4. 主观权衡与多模型比较契约

每个方案关联 `Criterion`（评价标准）、`ImpactClaim`（影响主张）、`Constraint`（约束）、`Preference`（偏好）和 `ScenarioRun`（情景结果）。

评价标准记录提出者、含义、单位或定性尺度、受影响者和依据。个人可以记录排序、可接受范围、可选权重及不愿交易的底线，并选择披露范围。不得将他人的未填权重推断为零，也不得从文字情绪强度自动生成政治权重。

个人加权比较仅适用于其确认可比较的标准；保留未量化维度和全部输入。不同人的分数不自动求和，不将其解释为可互相比较的幸福或痛苦。系统展示“对谁更好、对谁更差、基于何种假设”，而非一个全体通用的伦理得分。

约束分别记录适用法律、共同体宪章或参与者主张，以及提出、争议、采纳适用或不适用的处理状态和理由。底线主张不是自动否决权；适用性争议不能以多数票或积分消除。可行域为空时保留无协议、修订、暂缓或外部转介。专家需披露方法中的价值假设，不能仅凭专业资格确定共同体风险容忍度。

完整 Batch 1 区分既有适用硬约束、本案按程序确认的约束和待审单方主张。未采纳主张不自动将其送入交易池；正式保留意见、是否接受折算和程序参与分别记录，拒绝交易仍可讨论、举证和申诉。模型预测越界是潜在不满足约束，不直接构成现实违规。新分类及处理状态需显式映射，不静默修改现有 0.1.0 格式。

允许多个因果假设和模型并存，记录输入、版本、时间范围、适用域和已知局限。确定性计算可复算；概率模型注明分布与采样设置。任何支配关系或方案排序都限定在给定指标、偏好和模型内，不宣称发现了全局帕累托最优解。

分歧可同时属于事实、模型、价值或权限问题。稳健决策不固定等同最小最大后悔值；探索情景不冒充概率分布。自适应方案明确观测、决策触发、行动提前量及切换权限。本人确认的原文/译文版本与发布范围分别保存，任一文本修改后重新确认。

方案分支固定所依据的证据、模型及规则版本，允许比较参数差异而不覆写已生效底线。基线变化须显式重评，不能自动更新冻结表决的依据；分支通过筛查也不等于已获执行授权。争议事实保留主张和确认范围，不强制融合成“唯一正确事实”。

冻结后仍可追加误译纠正或撤回发布许可；发布许可、表达确认与表决实质性复核独立记录。普通评论撤回不自动中止表决；重大影响须有权裁定，并由有签令权的主体签发适用保护令。回退原文不能超出原文披露权限。低后悔值不豁免安全/权利底线。计量规范包含物质口径、单位、参考基准、时间分桶覆盖、聚合方式与方向性不确定性，样本数量足够不等于持续观察充分。

血缘可以登记引用关系和辅助复核，但某条 MATERIAL_PREMISE 边是否成立仍需具名依据；无边不能证明无影响。发布撤回停止后续不合许可的展示，既往冻结快照受控保留，新的脱敏版另存；不承诺回收外部已下载副本，不自动撤销历史决定。

## 5. 条件承诺与履约边界

条件承诺的最小字段：承诺主体、关联案件及方案版本、条件、计量口径、数据来源、截止时间、资源或义务、授权依据、核验者、争议期、失效及撤回规则。

例如，联盟甲承诺提供 40 个测试资源单位，条件为联盟乙在截止前确认提供 60 个单位且双方数据使用方案通过各自授权审查。首版通过人工核验和虚构回执演练，不连接真实算力调度。

总体承诺与分期履行工单分别保存：承诺记录总义务和已核实履行，工单记录排队、受阻、就绪、实际人工交接、回执及取消。授权通过只产生就绪资格，实际交接前仍重验；上传外部回执不自动证明履行真实。取消工单可按规则释放预留，但不解除承诺的未履行义务，变更义务须单独获得授权。履行后的争议通过关联申诉处理，不删除原有事实。

同一承诺在首版仅允许一种资源类型；涉及不同资源分别记账。对已受控的资源做预留与防重复分配，对外部资源标明核验依赖；不能保证发现其他系统中的隐藏重复承诺。部分履行、超时和解除须有明确记录，不允许以重试重复发起行动。

自动履约仅作为后续受限连接器：限定可控制资产、可验证条件、责任与救济。传感器观测、违约判断和处罚决定分别存储。关税、公共权利或其他机构的资格不会因导入一条决定而自动改变。

少数意见可附可观测预警，也允许无法量化的异议。阈值、单位、时间窗、数据有效性和处理权限须明确；越线默认产生复核请求，不证明过错。预先授权的紧急临时保护与最终处罚分开，设范围、期限、通知、复核和救济。案件、申诉、保护令、工单和总体承诺分别保存状态；申诉进度不产生暂停效力，任何适用且有效的保护令均可阻断对应动作。其他资格、资源和阶段条件独立检查。详细契约见 [RC 并行状态](architecture/batch1-rc1-spec.md#4-单一保护令权威源与并行状态)。

临时保护可能产生无法完全逆转的延期或收入损失，需记录副作用和补救；不能以“可逆”标签替代审查。到期旧令失去阻断力并升级；若独立前置条件全部满足，交接可以继续，不要求等待人工解除旧令。延期须新有效授权和新令。Batch 1 仅暂缓平台内未交接工单及通知人工复核，人工协查函只作为经授权的待审材料，不宣称冻结外部银行资产；实际支付由获授权财务人员处理，真实试点须满足 G4 与 PILOT_AUTHORIZED。

## 6. 案例包：首版的互操作边界

目标首版实现结构化 JSON 案卷导出和本地校验；导出是协议准备工作，不代表已实现联邦网络。完整导出目标如下，不能视为本轮已实现字段：

| 字段组 | 必备内容 |
| --- | --- |
| 来源与版本 | `schema_version`、`source_node_id`、`community_id`、`case_id`、`case_version`、`exported_at`；ID 在来源命名空间内解释。 |
| 完整性 | 文件清单、内容摘要和附件摘要；`integrity_only` 标记表示摘要不证明来源真实。 |
| 程序与权限 | 宪章/规则版本、程序类型、`mode`、授权核验状态、约束力声明及适用范围。 |
| 案件内容 | 问题、影响范围、来源证据、方案、模型、经许可的偏好、协商结果和异议。 |
| 结果与执行 | 建议或决定、条件承诺、执行回执、独立核验及未完成事项。 |
| 救济与状态 | 申诉、暂停、撤回、更正及状态观察时间；缺少更新不能解释为仍然有效。 |
| 隐私与复用 | 公开/受限级别、用途、必要遮盖、无法提供的附件清单和原因。 |

公开包不导出个人秘密选票、身份映射或未获授权的敏感偏好。受限包也必须有合法处理依据和接收方权限。内容被遮盖后要重新生成包摘要，并说明其是导出版，不冒充原始完整案卷。

Batch 1 快照使用带 SHA-256 清单的版本化 JSON，来源认证明确报告 NOT_SIGNED_BATCH1_BASELINE。文件与清单同时被替换仍可能匹配，摘要核对不证明来源可信；当前效力和外部控制须分别核验，不自动互认。资料类别的保存/销毁计划和恢复完整性不能在简化接口时丢失。

派生内容默认保留全部输入的访问限制和用途交集；来源可信度、发言确认、保存要求分别表达，不能统一取“最严格密级”。放宽披露需有权程序和新版本，不能靠摘要或统计形式绕过。导出允许范围内的对象、依赖边、策略/模板版本及隐藏依赖说明；接收方缺少相应策略语义时隔离或只读，不默认公开或恢复效力。

目标首版校验字段与引用一致性、已知版本、摘要和隐私白名单。后续接收方不得执行导入文件内的代码、指令或外部资源地址；未知强制字段与不兼容版本进入隔离审阅，而非静默忽略。

当前只提供 [Schema 0.1.0](../specs/case-packet.schema.json) 的 `simulation_gate_review` 配置：虚构证据、开轮授权、参与审计、底线与三项门控。它不包含完整决定、承诺、申诉历史、附件清单或签名；`VALID` 不证明真实性、完整性摘要或执行资格。其他字段不得混入此配置，后续明确扩展配置与迁移规则。完整格式目标与当前可运行子集的区别见 [决策内核第 8 节](architecture/decision-kernel.md#8-case-packet-离线配置与检查边界)。

## 7. 跨节点互认：第二阶段

两个独立运营者准备好后，增加签名、签发者信任清单、密钥轮换/撤销、记录状态查询和受限导入。签名格式及规范化方法在实现前选用成熟标准并固定版本，不自研密码学算法。

接收流程必须分为：格式与完整性校验、来源认证、状态及撤销检查、权限范围核验、本地规则适用审查、人工接受或拒绝。每一步单独记录结果。

- 签名有效不代表证据正确，也不代表接收方承认其法律效力。
- 互认按记录类型和范围制定；A 信任 B、B 信任 C，不意味着 A 信任 C。
- 无法确认最新撤销或暂停状态时，不授予新执行资格；可保留为历史参考。
- 重复包、乱序更新和撤回消息以来源 ID 与版本去重；不覆盖本地原决定或静默复活已撤回记录。
- 跨节点关联身份须有明确目的和依据；不默认建立全球可追踪的人口标识。
- 冲突决定按预先约定的管辖或升级程序处理；没有协议时保留分歧，不由平台制造一个全球终审层。

适用法、审理程序/机构、承认范围与执行地点分开记录。“影响地优先”是协作政策候选，不宣称为普遍冲突法；标准不可比较时不能自动取“最严格”。互认还需核对程序证据的真实性与状态，不能仅相信来源节点填写的响应率或申诉期。

节点退出时提供允许转移的数据、规则和未履行义务记录。迁移不等于接收方继承原有授权，不取消已存在的责任，也不保证外部服务继续提供资源。

迁移先隔离导入、恢复只读，再核对新运营者、密钥、撤销状态、外部资源和旧端停止新交接的安排。成员只能导出其获准取得的材料，不承诺人人可取得所有历史私密卷宗，或失联后无缝恢复真实履约。

Batch 1 的恢复清单逐项区分资料恢复、来源验证、当前效力与外部重绑定，列明缺件、责任人和阻塞动作。服务器搬迁不自动撤销所有既有授权，也不自动继承权限；无法核验的相关动作不得恢复。完整跨节点认证与活跃执行移交仍属 Batch 2。资料按公开、受限和隔离类别处理；密钥持有不是访问授权，保存/销毁按适用要求及救济需要制定，不能统一承诺永久保留或申诉期后全部销毁。

## 8. 平台自身治理

平台规则分为技术协议、共同体程序和模型配置三个版本层。软件维护者可修复缺陷，但不能以发布软件的方式修改成员资格、已冻结的票权或已作出的决定。

冻结边界是轮次的资格、规则与依据版本，不是禁止案件继续接收证据。新材料、申诉及勘误可以追加；实质变化中止受影响轮次并重新确认，历史记录不覆盖。格式版本、文档版本和运行中的宪章版本分别标识。

首版采用版本化业务记录和阶段快照，不要求完整事件溯源重放。成功转换的业务和 APPLIED 审计原子提交；预期拒绝不改变目标业务，故障另记受控诊断，提交结果未知先核对再重试，详见 [RC 三路审计](architecture/batch1-rc1-spec.md#5-三路审计幂等与不确定结果)。记录不可静默覆盖与敏感资料分级保存同时成立；历史审计不要求全部明文永久公开，也不把哈希当匿名化。

| 变更 | 提议与审查 | 生效方式 |
| --- | --- | --- |
| 技术格式或软件 | 维护者提出变更说明、兼容性与测试，受影响运营者审阅 | 明确版本与迁移；升级不自动改变共同体宪章。 |
| 共同体规则 | 按宪章提出、讨论、授权，披露利益冲突 | 未来轮次生效；实质影响当前案件时暂停并重新取得所需授权。 |
| AI 或模型 | 模型负责人披露输入、版本、评估及变化，主持与审查角色确认 | 冻结到轮次；安全修复中止受影响轮次并留痕。 |
| 紧急暂停 | 已授权运营或安全责任人提出范围、理由与恢复条件 | 有期限与独立复核，不能借暂停更改结果。 |

首版人工记录上述流程；不需要先建设全球治理委员会。公开资助和关键利益冲突，保留兼容版本的导出能力。协议、软件、模型和数据的许可分别明确；在许可文件建立前不宣称本项目已按某种开源许可证发布。

模板提供虚构案例和待本地核验项，不代替章程或任命。发布记录分别绑定构建、数据格式、动作注册表、模板、迁移检查及对应准入证据；软件回退不能消除已生效义务。维护人员无权通过升级改变冻结轮次、许可或真实试点范围。

## 9. 协议验证顺序

SPEC_FROZEN 登记经审阅的契约范围、版本和摘要；IMPL_CONFORMANT 登记对应代码在真实 PostgreSQL 中的 FT/PT、其他权限/隐私验收和历史回放证据；PILOT_AUTHORIZED 登记具体共同体、额度、期限、人员、数据与应急安排。三者分别保留有效及撤回状态；当前均未达成。合成测试与获准历史回放先行，真实试点必须具备匹配的三类依据，不能用文档标题或离线测试替代。

MVP 验证本地授权和案件闭环、案卷完整性及脱敏导出；下一阶段验证两个节点之间的伪造签名、过期授权、重复与乱序消息、撤回、离线及拒绝互认；真实执行连接器再验证幂等、防重复分配、暂停、故障与对账。软件校验通过只说明实现满足这些契约，不证明民主正当性或伦理优越性。
